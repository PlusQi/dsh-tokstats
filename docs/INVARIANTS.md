| TS-35 | **「面」用 border-l2、「线」用 border-l1**（边框层级契约，2026-10-26）：宿主亮色主题里 `--dsw-alias-bg-base` 与 `--dsw-alias-bg-layer-1` **同为纯白**（都指 `--dsw-static-neutral-bluish-00`），卡片与页面底色完全同色，于是边框是唯一的分层手段。而 `--dsw-alias-border-l1` 亮色是 `#0000000a`（4% 黑），压在纯白上合成 `#f5f5f5`、对比度仅 **1.09:1**——八块卡片会连成一片，读者数不出有几张卡（这是浅色主题截图的实测结论，不是推测）。因此**三处卡片面**（`.dsh-tokstats-skCard` / `.dsh-tokstats-kpi` / `.dsh-tokstats-card`）必须用 `--dsw-alias-border-l2`（`#0000001a`，10% 黑 → `#e5e5e5`，1.26:1）。**另一半同样硬**：**三处分隔线**（`.dsh-tokstats-chartPlot` 底边 = 0 刻度、`.dsh-tokstats-gridLine` 网格线、`.dsh-tokstats-foot` 页脚横线）**继续用 l1**——它们的语义是「一条线」而不是「一块面」，跟着加重会与卡片边框抢层级（页脚曾误用 l2，比卡片还实，已回退）。骨架卡同改：首屏骨架与成品卡同圆角是既有约定（跳版会闪），边框不同样会跳。判据只针对这三个类名，不禁止别处用 l1/l2；深色主题下 l1（`#ffffff0f` 5.9% 白）/ l2（`#ffffff1f` 12.2% 白）同样满足「面重线轻」，改后深色卡边对比度 1.36:1 → 1.68:1，不是只对亮色生效的补丁 | `test/client-tokstats.test.mjs`「TS-35：卡片「面」用 border-l2、「线」仍用 border-l1——亮色下卡与页同色时靠 l2 才分得开」（六个类名逐个断言：三处面必须是 l2 且不得退回 l1、三处线必须仍是 l1）。**反向验证**（2026-10-26，两条各记一次实测）：① 把 `.dsh-tokstats-card` 改回 l1 → 红；② 把 `.dsh-tokstats-foot` 也改成 l2 → 红（防「一次改全」式过度修正）。**目检**：无头 chromium 渲染真实组件树 + 真实 CSS，亮/暗两套主题各一次，逐像素量卡边对比度（1.09 → 1.26 / 1.36 → 1.68） | L2 + 目检 |

## 维护规则

1. **新增不变量**：先在此表加行（含证据列），再去改代码/测试；不得先写代码后补编号。
2. **证据列不得为空**。只靠评审的条目标 `L0` 并写明「依赖评审」——把 L0 写成 L1/L2 是空壳（曾发生：旧 SPEC 声称「零运行时依赖由 guard 静态检查」，而 guard 当时并无 import 检查）。
3. **改证据形态时**（guard 项改名、测试重命名、断言移入新文件）必须同步本表指针，否则指针失效即为漂移。
4. **作废不变量**：整行标「已废弃（日期 + 原因）」，保留行不删除，避免编号复用造成历史误读。
5. **不改代码里的旧编号注释**：历史 `I*` 注释保留原样，靠下表映射到新 ID；改注释会触碰 `lib/index.js` 与全部测试文件，触发「按变更范围读取」表里的 `npm test` + 重启目检，收益不抵风险。
